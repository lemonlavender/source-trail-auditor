# Source Trail Auditor

[English README](README.md)

Source Trail Auditor 是一个可复用的 Skill，面向编辑、分析师、研究人员、产品团队和开发者，用于在采取行动前审查 AI 辅助生成的网络研究稿。它把正文和链接转换为原子化主张清单，检查每个来源实际支持什么，区分官方操作页与背景阅读页，并给出解决关键缺口的最短核验路径。

项目通过声明式 `.ipollowork-plugin` 安装包支持 [iPolloWork](https://github.com/Devin-AXIS/iPolloWork)，不需要本地服务、凭据或额外运行时。

## 解决的问题

AI 辅助研究经常把看似合理的陈述放在相关链接旁边，却没有回答几个影响决策的问题：页面是否直接支持该句、来源范围是否比原文更窄、主张是否仍然有效、链接是否真的是完成所述任务的页面。Source Trail Auditor 明确呈现这些关系，不把链接数量或官方域名本身当作证据。

## 适用场景

- 在采购或部署前审查带链接的产品比较。
- 检查政策、合规或市场简报的逐项可追溯性。
- 审核包含可能变化事实的 AI 生成答案。
- 找到建议背后真正用于配置、下载、查看价格、政策或状态的官方页面。
- 把未解决的研究缺口转换为按优先级排列的核验清单。

## 已实现能力

- 将可核查正文拆分为原子化主张 ID。
- 把已检查的证据标记为 `supported`、`partial`、`contradicted` 或 `unverified`。
- 记录来源发布者、页面类型、日期、访问状态和与主张相关的角色。
- 区分官方操作页、产品概览页和背景材料。
- 标记需要“截至日期”或当前复核的易变主张。
- 识别最终依赖同一原始来源的重复说法。
- 生成 `P0`–`P2` 核验步骤和有边界的改写建议。
- 无法浏览时可依据用户提供的摘录工作，并在输出中明确限制。

## 工作流程

1. 提供研究稿、引用 URL 或摘录、研究要支持的决策以及截至时间。
2. 要求模型使用 `source-trail-auditor`。
3. Skill 创建原子化主张和来源账本。
4. 宿主支持浏览时打开引用页面；否则只依据提供的摘录下结论。
5. 将每个主张映射到精确证据，并检查范围、时间和来源独立性。
6. 为原文中的具体操作识别直接官方页面。
7. 输出决策结论、证据表、时效队列、核验路径和改写建议。

## 输入与输出

### 输入

- 答案草稿、备忘录、研究简报或建议。
- 其中引用的 URL、页面摘录或附件。
- 研究需要支持的决策或问题。
- 涉及当前事实时的截至时间。

### 输出

一份包含十个部分的 Markdown 审计报告：范围、结论、主张来源矩阵、来源账本、官方操作链接、时效队列、来源独立性、核验路径、改写建议和覆盖边界。

## 端到端示例

仓库内的[研究材料](examples/research-packet.md)要求判断一个虚构团队是否应为所有客服启用助手。原稿夸大了全球可用性，把企业版隐私规则扩大到所有套餐，并使用产品概览页代替配置页。

调用示例：

```text
使用 source-trail-auditor 审核 examples/research-packet.md，截至 2026-10-17。保留每项事实主张并生成完整报告。
```

预期结果见 [examples/expected-audit.md](examples/expected-audit.md)：结论为 `not-ready`，包含五项原子主张、两项相互矛盾的主张、缺失的官方操作页以及三个按优先级排列的核验步骤。

## 在 iPolloWork 中使用

1. 从 GitHub Release 下载 `source-trail-auditor-1.0.0.ipollowork-plugin`。
2. 打开 iPolloWork，进入 **扩展 → 插件 → 添加 → 文件**。
3. 选择下载的安装包，检查发布者、版本和唯一的 Skill 资源。
4. 点击 **安装插件**，确认插件及 `source-trail-auditor` Skill 已启用；如有提示则重新加载项目。
5. 把研究稿和来源材料加入项目。
6. 新建任务并输入：`使用 source-trail-auditor 审核 <文件>，截至 <日期>，并保存完整 Markdown 报告。`
7. 检查输出是否包含主张来源矩阵、官方操作链接、时效队列和覆盖边界，然后从项目中导出或保存 Markdown 文件。

如需使用独立 Skill 包，解压 `source-trail-auditor-1.0.0-skill.zip`，再从本地 Skill 页面导入其中的 `source-trail-auditor` 文件夹。

## 构建与打包

要求 Node.js 20+ 和系统 `zip` 命令。

```bash
npm test
npm run package
```

构建会在 `dist/` 中生成 iPolloWork 安装包、独立 Skill ZIP、源码 ZIP 和 `SHA256SUMS.txt`。所有压缩包都从干净 staging 目录创建，并统一文件时间戳。

- 桌面环境：iPolloWork 0.50.20、macOS 15.5 arm64、OpenCode 引擎。

## 功能限制

- Skill 无法证明不能打开的 URL 内容；会明确标记仅有摘录或不可访问的材料。
- 即使页面来自官方，也不能据此保证来源真实、无偏、完整或相互独立。
- Skill 不替代实际业务、法律、医疗、金融或安全决策。
- 当前产品可用性和政策仍需直接检查对应的权威页面。

## 常见问题

### 会自动搜索网络吗？

只有宿主提供浏览能力且任务允许时才会浏览。无法浏览时，Skill 审核用户提供的摘录，并列出尚未打开的 URL。

### 为什么官方页面仍可能不够？

权威性取决于具体主张。产品首页可以是官方页面，但未必支持价格、当前部署范围、政策或精确配置路径。

### 多个来源能证明主张吗？

不能直接这样判断。多个页面可能重复同一项未经支持的说法，或都追溯到同一个来源。报告会分别记录直接支持关系和来源独立性。
